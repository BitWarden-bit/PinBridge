# PinBridge 当前进度（2026-08-15）

## 本轮已完成

### 调试启动生命周期

- 启动目标后使用主 PE 镜像的正常 `AddressOfEntryPoint`，不做额外的壳识别或自定义 OEP 推断。
- agent 在主镜像加载回调中安装一次性入口断点；入口指令执行前停下，断点命中信息可由 `BP_LIST` 查询。
- CLI、TUI、桌面 UI 的目标启动默认开启入口断点。
- 客户端启动函数在返回前等待“控制端口已打开”以及“确实已经停在入口断点”两个条件。
- `--no-entry-bp` 保留给需要直接运行目标的低级/自动化场景；该模式不会等待入口停点，也不会启用脚本启动闸门。

### 脚本生命周期

- 入口断点模式下，启动目录插件和入口断点前提交的 `script run` 只会先编译，顶层代码和 `pb_init()` 延迟到首次入口停点后执行。
- 首次入口停点打开脚本启动闸门；之后目标恢复运行，脚本仍可通过 query server 热加载、替换和卸载。
- 入口停下后可以从前端、CLI、MCP 或脚本执行 `context`、寄存器/内存读写、下断点、配置 trace，再显式 `resume`。

### PBTR trace

- trace 选项是可组合的：执行（含机器码）、内存值、分支、寄存器快照、syscall、异常/context-change 可以同时开启。
- 寄存器快照采用线程基线加变化掩码；已覆盖 GP、RIP、RFLAGS，以及 XMM/YMM/ZMM 0-31（分别按 128/256/512 位宽记录；Pin context 不提供的寄存器会跳过）。
- syscall/异常事件可写入 PBTR，并能在 Python `TraceFrame` 中与指令、寄存器、内存和分支事件关联。
- 重复记录支持无损 RLE；解析器保留原始 record JSONL，也提供组合后的 `TraceFrame` 视图。

## 尚未完成 / 明确边界

- PBTR 不是每条指令默认携带完整上下文；寄存器、syscall、异常等仍是显式选项，开启后会增加体积。
- MXCSR、x87/MMX、AVX-512 opmask `K0-K7`、段寄存器、控制/调试寄存器和 AMX tile 等扩展上下文尚未接入 PBTR 寄存器快照。
- 目前的压缩是无损重复记录 RLE 与寄存器变化掩码，不是循环体识别；尚未提供“循环执行 N 次”的结构化摘要，也不会在寄存器、内存、地址或线程变化时强行合并。
- `TraceFrame` 是 Python 解析层的组合视图，原始 PBTR 仍按 record 存储；尚未定义跨语言统一的二进制 `TraceFrame` ABI。
- syscall 事件本身不附带机器码；要看到 `syscall` 指令的地址、字节和反汇编，必须同时开启执行/机器码记录并设置合适地址范围。
- exception/context-change 已提供六类原因名称、变化前后 IP/有效位和可靠 Python 投递，但尚未做完整异常栈、调度切换及各平台 `info` 的逐原因扩展 schema。
- 尚未完成真实 crypto.exe 的端到端新 trace 样本、压缩率和性能基准；需要在允许启动 Pin/目标程序的环境中补测。

三条数据流

A 事件热路径

高频 · instrumentation time 决策 · 零成本
1目标指令 → Pin JIT 重编译 → 插桩点
2范围过滤 RANGE / HOOK / syscallfilter（编译期折叠）
3固定 IARG 抓取：寄存器 / 内存操作数 / 分支 / 指令字节 / 值
4写 ring（64K 定长槽 · 零分配零 I/O · 不 panic）
5消费者被动翻页：查询线程 / 脚本线程 / 录制 drain
!同步只用 pb_pin_mutex_*；std::sync::Mutex 进热路径会 9/10 崩溃

B 控制 / 观测面

低频 · 请求-响应 · loopback RPC
1CLI / TUI / UI → pinbridge-client → query_server
2控制：stop/resume · read/write · bp(64) · hooks(4096)
3单步：si/so（落点回调内停泊，非异步挂起）
4观测：modules/threads/exports · setreg · syscallfilter · engine
5断点命中 → 停泊 → 改上下文 → resume
!stop/resume 与调用线程配对；跨线程 resume 直接杀进程

C 脚本 & 录制/重放

污点分析主链 · 编排 → 录制 → 离线重放
1脚本线程每 tick ~5ms：拉事件页 ≤2048 条 + 停点快照
2插件 pb.* 动作 = 一次 loopback RPC（微秒级）
3pb.trace_start → 独立 slab 录制 kind 9/10/11
4drain 线程落盘 .pbtr（PBTR v1 · 88B 记录流）
5离线 taint.py：前向污点 + 后向切片（capstone）
!具体 EA 消灭别名 → 无需指针分析；ring 溢出 = 窗口作废
污点分析三层路线图
① 编排层 · 已完成
内嵌 CPython 多插件脚本宿主：事件订阅、断点/hook、内存与寄存器读写、停走单步、符号解析。pb_init / on_event_batch / on_bp_hit / bp_set / hook_set / read_mem / get_reg…
② 录制通道 · 已交付 (ABI v1.5)
把「跑过的那段执行」无损落盘：trace start/stop/tracest，独立 1M 槽 slab，Pin 内部线程 drain。档2 抓取：exec_bytes(9) / mem_value(10) / marker(11) → .pbtr。
③ 重放分析层 · 原型中
纯 Python 离线引擎：pbtrace.py / recorder.py / taint.py，前向污点传播 + 后向切片（capstone 解码）。具体 EA 消灭别名，不做指针分析。16 个离线单测。
设计哲学：Pin 负责指令重编译与插桩回调；pinbridge.dll 把 C++ API 冻结成 C ABI；pinbridge-agent.dll 做「过滤插桩 → 定长事件 → 有界 ring」外加控制/脚本/录制三个旁路；协议/客户端 提供统一二进制查询面； 前端 只消费聚合与水位；离线 replay 在录制轨迹上做污点与切片。
CRT 隔离类型隔离内存所有权隔离线程隔离I/O 隔离 900 万事件/s vs 60 帧/s热路径写 ring 永不阻塞 UI
